# Record Collections, Quantitative Reconciliation, and Charts

## Attribute Capacity Between Primary View and Secondary Detail

- **When** displaying a collection of records, include in the primary row or card only the attributes required to identify a record, compare records, and trigger the primary action so horizontal siblings fit within the container; for wide 2D data tables on narrow viewports (`320px`), scroll the table horizontally inside its own wrapper (`overflow-x: auto`) so the page viewport never scrolls horizontally, and move remaining detail attributes into a secondary disclosure view.
- **When** an item in a collection opens secondary details, bind that trigger to the whole item (backed by a semantic `<button>` or `<a href>` for keyboard access) if opening it is the sole action and text selection is not needed; otherwise bind it directly onto the item's primary identifier (`<button>` or `<a href>`) instead of adding a repeated detail button on every item. *Guardrail*: Never nest interactive controls inside a clickable item wrapper.
- **When** showing secondary details for an item selected from a collection, open a side drawer or detail pane so surrounding items keep their layout positions during sequential inspection; expand inline inside the collection only when the task requires comparing multiple items' details simultaneously.

## Column Alignment, Quantitative Integrity, and Per-Row Action Weight

- **When** a column or readout displays numbers compared by magnitude across rows, live counters, timers, or prices, end-align the values (`text-align: end`) and apply `font-variant-numeric: tabular-nums` so digits of equal place value align vertically.
- **When** a column displays text identifiers or strings read character-by-character rather than by numeric magnitude, start-align the column (`text-align: start`), adding `font-variant-numeric: tabular-nums` (plus `slashed-zero` where `0` and `O` can be confused) when every value in the column shares a fixed character pattern.
- **When** the same metric appears in multiple places on screen or an additive total or two-value difference appears beside its component figures, derive repeated figures from one state source and compute displayed sums and differences from the displayed rounded components at uniform decimal precision so on-screen arithmetic reconciles digit for digit. *Guardrail*: Never hardcode duplicate figures separately across summary cards and charts, and never round a displayed sum or difference independently of its displayed addends.
- **When** displaying a relative delta or percentage change, name the comparison baseline in the same phrase, color the delta by whether the change helps or harms the domain goal rather than by `+`/`-` sign, and render zero change or missing-baseline cases in neutral muted text (`+N (new)` when prior baseline was `0`; muted `—` when no prior baseline exists). *Guardrail*: Never show a bare delta without its comparison period/target, never color rises in error rate, latency, cost, or churn green (or favorable drops red), and never apply positive/negative status color to `0`, `0.0%`, `+100%` from zero, or extreme small-denominator spikes (`>999%`).
- **When** rendering a cell or metric whose value is zero versus unrecorded/inapplicable, format measured zero with its unit and precision (`0`, `$0.00`, `0.0%`) and render missing or inapplicable values as a muted em dash (`—`) paired with an accessible label stating no value is recorded. *Guardrail*: Never conflate measured `0` with missing data, and never render raw `null`, `undefined`, `NaN`, `N/A`, or an unlabeled blank cell.
- **When** rows in a list or table include per-row actions, treat the entire collection view as one decision scope under `SKILL.md` (*Action and Control Hierarchy*).

## Peer Geometry Locking, Virtualization, and Reordering

- **When** peer cards sit side by side in a multi-column grid row, clamp variable-length text slots to a consistent maximum line count and pin the card footer/action bar to the bottom edge so peers in the same row align cleanly across their bottom baselines.
- **When** a list or table can render more than `50` items, virtualize the collection (or apply `content-visibility: auto` / pagination) rather than mounting every DOM node at once. *Guardrail*: Never `.map()` unbounded arrays directly into the DOM without virtualization or pagination.
- **When** a list, table, or board supports drag-and-drop reordering or cross-column movement, provide a single-pointer control (move up/down or move-to menu) and a keyboard interaction that perform the exact same reorder.

## Data Charts and Visual Encoding

- **When** rendering a coordinate chart, anchor bar and count y-axes at `0` with evenly spaced round tick intervals (integer ticks for integer counts) whose top tick exceeds the data maximum, and space x-axis ticks on one uniform interval that fits the container without label collision. *Guardrail*: Never omit the y-axis scale, never truncate a bar or count y-axis above `0` or let marks clip the top tick, and never place an irregular final step on a time axis.
- **When** plotting discrete period totals or forecasts on a line chart, connect measured points with straight segments and switch forecast segments past the last recorded period to a dashed stroke. *Guardrail*: Never smooth discrete period totals with bezier/spline curves that invent intermediate values, and never draw projections with the same solid stroke as recorded history.
- **When** assigning chart series colors and legends, reserve the primary accent/data hue for the focal series while rendering comparison series in distinct semantic or neutral tones (keeping one hue per entity across sibling charts on the same screen), omit the legend on single-series charts, and render multi-series legend swatches using the exact stroke, fill, and dash pattern of each series currently plotted. *Guardrail*: Never render a legend for a one-series chart or an unplotted empty series, and never reuse the same hue for different entities (or different hues for the same entity) across charts on one screen.
- **When** annotating a target threshold or event spike on a chart, render thresholds as a `1px` dashed reference line labeled at its end and route event callouts via a vertical leader line into a dedicated non-overlapping band above the plot reserved only when event annotations exist, measuring label layout after web fonts load. *Guardrail*: Never reserve a blank annotation band when no annotations are present, and never let axis ticks, threshold text, or leader lines collide with plotted marks or other labels.
