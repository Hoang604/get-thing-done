# Motion, Pointer/Gesture Input, and Overlays

## Motion Mechanics, Timing, and Input Capabilities

- **When** animating interactive state changes that a user can reverse mid-flight (hover, toggle, disclosure, drawer open/close, button press), drive them with CSS `transition` listing the exact changing properties (`scale, opacity, translate, transform, filter`) in `transition-property`, and disable initial mount animations (`initial={false}`) on state-swap containers so default states do not animate in on page load. *Guardrail*: Never use CSS `@keyframes` (`animation:`) on toggled interactive states (`.open`, `:hover`), never use `transition: all` or `transition-all`, never set `will-change: all` or apply `will-change` preemptively where no first-frame stutter exists (remembering `will-change` on `transform`/`filter` creates a containing block that breaks `position: fixed` descendants), and never set `opacity: 0` in a base rule that only an animation reveals (put the hidden state inside the `from` keyframe with `animation-fill-mode: both`).
- **When** setting feedback timing on high-frequency interactions (keystrokes, row hovers, action reveals, tab switches, button presses), respond instantly or within `150ms` (`ease-out` on `opacity` or `background-color`) and always leave a persistent static cue (color, icon, or label) once motion settles. *Guardrail*: Never communicate state change through motion alone, and never stage or keyframe-animate hover-revealed controls.
- **When** animating element entrances and exits, make exits shorter and subtler than entrances (using full-distance slide-out only when the off-screen edge indicates where the dismissed surface lives, and using `@starting-style` with `transition-behavior: allow-discrete` for `display: none` popovers/dialogs). *Guardrail*: Never stagger routine task controls or cross-fade icon swaps slowly.
- **When** adapting motion and pointer styles to user preferences and device input, gate spatial movement, scale, and blur behind `@media (prefers-reduced-motion: no-preference)` (falling back to a `150ms` opacity cross-fade and disabling parallax and decorative autoplay loops under reduced motion), provide a visible pause/stop control on anything moving, blinking, or updating on its own for more than `5 seconds`, and wrap `:hover`-only styles inside `@media (hover: hover)` (setting `-webkit-tap-highlight-color: transparent` where a control draws its own pressed state). *Guardrail*: Never leave bare `:hover` styles unguarded where touch taps latch them into a stuck selected state.

## Overlays, Focus Containment, Scroll Isolation, and Gesture Cleanup

- **When** considering an overlay (modal, drawer, popover, menu, sheet, or command palette), exhaust inline display and progressive disclosure first (for collection-item details see `references/data-collections.md`), reserving modal dialogs strictly for interactions that require deliberate user interruption or focus isolation, and mount popups/overlays via `<dialog>`, the Popover API, `position: fixed`, or a portal so ancestor `overflow: hidden|auto` containers never clip them.
- **When** opening a modal dialog or overlay, implement it with `<dialog>` opened via `showModal()` or a container carrying `role="dialog" aria-modal="true" aria-labelledby="..."` with `inert` on background content, move focus inside on open (to the first interactive control, or the least destructive button on destructive confirmations), cycle `Tab`/`Shift+Tab` within the modal, close only the topmost open layer on `Escape` (tooltip $\rightarrow$ menu/popover $\rightarrow$ dialog), return focus to the invoking trigger on close, and set `overscroll-behavior: contain` on scrollable overlay bodies so scroll momentum never leaks to the page behind (on SPA route transitions, update `document.title` and move focus to the new view's `<h1>` with `tabindex="-1"` or `<main>`).
- **When** implementing custom drag, slider, or swipe interactions, scope `touch-action: none` and `user-select: none` to that element only while dragging, ignore or cleanly terminate secondary touch pointers mid-gesture rather than jumping coordinates, and attach `pointercancel`, `lostpointercapture`, outside pointer-up, `window` `blur`, and `visibilitychange` listeners to release pointer capture and reset drag state immediately.
