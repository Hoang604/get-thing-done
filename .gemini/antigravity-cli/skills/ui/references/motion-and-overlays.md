# Motion, Pointer/Gesture Interactions, and Overlays

Apply the rules below when the interface animates state changes, responds to pointer or gesture input, or renders overlays (modals, dialogs, drawers, popovers, menus, tooltips).

## Motion Mechanics, Timing, and Compositor Performance

- **When** animating interactive state changes that a user can reverse mid-flight (hover, toggle, disclosure, drawer open/close, button press), drive them with CSS `transition` or a zero-bounce spring (`type: "spring", duration: 0.3, bounce: 0`) so they retarget smoothly when interrupted, list the exact changing properties in `transition-property` (`scale, opacity, translate, transform, filter`), and disable initial mount animations (`initial={false}`) on state-swap containers so default states do not animate in on page load. *Guardrail*: Never use CSS `@keyframes` (`animation:`) on toggled interactive states (`.open`, `:hover`), never use `transition: all` or `transition-all`, never set `will-change: all` or apply `will-change` preemptively where no first-frame stutter exists (remembering `will-change` on `transform`/`filter` creates a containing block that breaks `position: fixed` descendants), and never set `opacity: 0` in a base rule that only an animation reveals (put the hidden state inside the `from` keyframe with `animation-fill-mode: both`).
- **When** setting durations and easings for high-frequency interactions (keystrokes, row hovers, tab switches, toolbar reveals, button presses), respond instantly or within `150ms` (`ease-out` on `opacity` or `background-color`), always leaving a static color, icon, or label cue behind when motion settles. *Guardrail*: Never use motion as the sole carrier of a state change.
- **When** animating element entrances or exits, make exits shorter and smaller than enters (sliding fully out only when spatial destination carries meaning like a drawer closing; for discrete `display: none` popovers/dialogs, use `@starting-style` and `transition-behavior: allow-discrete`). *Guardrail*: Never stagger routine interactions or animate tab/row-hover icon swaps with slow cross-fades.
- **When** adapting motion and pointer styles to user preferences and input capabilities, gate all movement, scale, and blur inside `@media (prefers-reduced-motion: no-preference)` (falling back to a `150ms` opacity cross-fade under reduced motion, and disabling parallax and decorative autoplay loops completely), provide a visible pause/stop control on anything moving, blinking, or updating on its own for more than `5 seconds`, and wrap all `:hover`-only styles inside `@media (hover: hover)` (setting `-webkit-tap-highlight-color: transparent` where a control draws its own pressed state). *Guardrail*: Never leave bare `:hover` styles unguarded where touch taps latch them into a stuck selected state.

## Overlays, Focus Trapping, Scroll Containment, and Interrupted Gestures

- **When** choosing whether to introduce an overlay, exhaust inline and progressive disclosure alternatives first, reserving modal dialogs for tasks that require deliberate interruption or protected focus, and ensure dropdowns, popovers, and modals escape any ancestor with `overflow: hidden` or `overflow: auto` via `<dialog>`, the Popover API, `position: fixed`, or a portal.
- **When** opening a modal or overlay, render it through the project's overlay component or macro (or directly in raw-HTML stacks, in either case implementing the underlying primitive with `<dialog>` opened via `showModal()` or a container carrying `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, and `inert` on the background surface), move focus inside on open (to the first focusable control, or the least destructive button on destructive confirmations), wrap `Tab`/`Shift+Tab` inside the dialog, dismiss the topmost open overlay on `Escape` (tooltip $\rightarrow$ menu $\rightarrow$ dialog), restore focus to the trigger element on close, and set `overscroll-behavior: contain` on every scrollable dialog, drawer, menu, or side panel so scrolling past its end never scrolls the page behind (on SPA client-side route changes, update `document.title` and move focus to the new view's `<h1>` with `tabindex="-1"` or `<main>`).
- **When** implementing custom sliders, drag surfaces, or swipeable control strips, scope `touch-action: none` and `user-select: none` to that surface during the gesture, keep the initial pointer (or end cleanly) if a second finger lands mid-drag rather than jumping to the new coordinates, and listen for `pointercancel`, `lostpointercapture`, pointer release outside the control, window `blur`, and `visibilitychange` to clear the dragging state and release pointer capture immediately so the next tap or drag works without a page reload.
