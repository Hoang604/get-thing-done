---
name: plan-increment
description: Harden an active boundary-plan artifact with runtime/performance, security, and REAL boundary test increments.
disable-model-invocation: true
---

**When** passing a single isolated call on minimal valid input does not establish that a milestone stays viable under the repository's real operating environment, read `references/perf.md` to derive runtime-and-performance rulings and update affected plan contracts.

**When** any milestone ships across a trust boundary where a party outside that trust domain could gain an unauthorized outcome through it, read `references/sec.md` to derive security rulings and update affected plan contracts.

**When** no repository rule excludes the plan's modified scope from automated testing and any milestone's current executable boundary contracts lack an up-to-date `Test Matrix`, read `references/test.md` to derive REAL boundary tests and update the plan.

## Steps

1. **Verify finalized plan and select active references.** Read the active plan (`implementation_plan.md` or `implementation_plan_round_<N>.md`). **When** the active plan still contains `## Open Investigations` or any `[OPEN: ...]` marker, stop immediately and report that the plan must be finalized before running `plan-increment`. Otherwise, before loading any reference, evaluate `perf`, `sec`, and `test` individually while holding the other references fixed: mark a reference `excluded` whenever a repository rule forbids applying it to the plan's modified scope (reporting that exclusion if the user requested it); otherwise mark it `active` when the user requested it; mark unrequested references `skipped` when the user explicitly restricted the run to named references, and otherwise mark each remaining reference `active` when its `**When**` condition holds for the active plan and `skipped` when it does not.
   *Done when* the active plan has zero `## Open Investigations` or `[OPEN: ...]` markers, every one of `perf`, `sec`, and `test` has an individual selection verdict (`active`, `skipped`, or `excluded`), and any user-requested reference blocked by a repository rule has been reported.

2. **Run active `perf` and `sec` increments first.** Read the reference file for each `active` `perf` and `sec` dimension and apply its principles before `test`. For each active `perf` or `sec` reference, inspect the code referenced by each affected milestone with `read_file` and, before editing the plan, evaluate every concrete site in that milestone governed by that reference's principles individually while holding the other sites fixed—ruling `no change` (citing what already closes it) or `amend` (stating the exact plan change required). Whenever codebase facts and the violated invariant uniquely determine the fix for an `amend` ruling, update every part of the active plan the fix affects—inspecting any newly touched file with `read_file` first so the plan stays self-contained—while preserving all `boundary-plan` invariants; whenever multiple incompatible external behaviors satisfy the invariant and neither the codebase nor the plan chooses among them, stop before editing that unresolved part and report the milestone, the violated invariant, and the competing behaviors to the user. Apply every `amend` ruling directly to every affected section of the active plan while preserving its `boundary-plan` structure (and `ArtifactMetadata`), and record the individual rulings in `#### Perf Rulings` or `#### Security Rulings` strictly inside milestones evaluated by that active dimension.
   *Done when* every active `perf` and `sec` dimension has evaluated every governed site individually across affected milestones, every uniquely determined `amend` ruling is reflected consistently across every affected section of the active plan (backed by `read_file` with exact `#L<start>-L<end>` manifest ranges and its rulings recorded in each evaluated milestone), and any unresolved external-behavior policy choice has stopped for user decision.

3. **Run `test` increment over the updated contracts.** Re-evaluate `test`'s `**When**` condition if `test` was initially `skipped` (not `excluded` and not blocked by an explicit user scope restriction) whenever Step 2 altered contracts covered by an existing `Test Matrix`. When `test` is `active`, read `references/test.md` and execute its procedure against the updated active plan (preserving `ArtifactMetadata`).
   *Done when* either `test` is `skipped`/`excluded` with zero stale `Test Matrix` contracts remaining, or `references/test.md`'s completion criteria hold on the updated active plan (including any `perf`/`sec` re-entry triggered by an `unguarded` reachable assumption).
