# Asynchronous Lifecycle, Data Mutations, and Live Announcements

## Geometry Preservation, Empty/Error States, and Live Regions

- **When** a region awaits asynchronous data or loads media, render a skeleton matching the populated layout's box dimensions, mark the updating container `aria-busy="true"`, declare explicit `width` and `height` (or `aspect-ratio`) on every `<img>` (`loading="lazy"` below the fold, `fetchpriority="high"` on the primary above-the-fold image), and surface slow or timed-out requests with an explicit status message plus retry/cancel controls. *Guardrail*: Never swap a content container for a bare spinner that collapses its height and shifts surrounding layout on load.
- **When** a collection query returns zero items, branch on the cause: if the collection has never held items, state what belongs there and render one primary creation action (when permitted); if an active search or filter produced zero matches, name the active query/filter and render an immediate clear/reset control. *Guardrail*: Never render a dead-end `"No data"`/`"No results"` label without a next action, and never hide permanent feature instructions solely inside a first-run empty state.
- **When** a fetch or mutation fails or permissions block access, retain all user-entered input, state plainly beside the affected region what failed and the concrete recovery step alongside an immediate retry or recovery control, and on `403` or read-only views state why access is restricted and how to request it. *Guardrail*: Never wipe form state on a failed request, never use blame, humor, `"Oops!"`, or `"Something went wrong"` in error copy, and never expose raw HTTP codes or stack traces as the primary user message.
- **When** a user-triggered mutation is in flight, keep the button's action label readable beside the progress indicator (or show parallel `…` in-progress copy resolving to completion state), set `aria-disabled="true"` on the active submit/action button so keyboard focus stays anchored on the control, and ignore duplicate activations in the handler until settlement. *Guardrail*: Never replace a busy button's text with an unlabeled spinner, and never set native `disabled` mid-request on the currently focused button (which drops focus to `<body>`).
- **When** announcing dynamic updates not already conveyed by focus movement or `aria-describedby`, populate a pre-mounted empty live region in the DOM—using `role="status"` (`aria-live="polite"`) for routine confirmations, toasts, and result counts, and reserving `role="alert"` (`aria-live="assertive"`) strictly for urgent untied errors—keep focus in the user's active control, keep toasts carrying an action (`Undo`) or error open until dismissed, and hold auto-dismissing status toasts for at least `5 seconds` while pausing the timer on hover and focus within. *Guardrail*: Never mount `role="status"`/`role="alert"` nodes conditionally in the same render as their message text, never announce success messages with `role="alert"`, and never put a required recovery action inside an auto-expiring toast alone.
