# Realtime Multi-User Synchronization Reference

> **Reference Notice**: This document is a domain reference, not a blind checklist. Before applying any primitive, architectural branch, or boundary rule below, inspect the target system's existing architecture, scale, operational constraints, and actual requirements to judge whether the mechanism fits the system under design or modification.

## 1. Closed Contract for Off-the-Shelf Primitive Delegation

When a synchronization path falls into a row of the contract table below and the target system's requirements call for that capability, bind directly to the primitive already installed in the repository for that plane—or integrate one of the listed off-the-shelf primitives when the repository has none for that plane—without re-implementing the underlying conflict-resolution, sequence-indexing, cursor-interpolation, or replication algorithm in application code.

| Data Structure & Invariant Scope | Canonical Resolution & Transport Mechanism | Mandatory Off-the-Shelf Primitives (When None Is Installed) |
| :--- | :--- | :--- |
| Cross-record business invariants, sequential identifiers, global quotas, or server-enforced authorization | Speculative local mutators reconciled via server-serialized transaction replay and atomic watermark diffs (Transactional Rebase / IVM) | `Zero`, `Replicache` (with `Reflect`), or Postgres logical-replication streams via `ElectricSQL` (Shapes) / `PowerSync` (Sync Rules) paired with `TanStack DB` and an idempotent outbox |
| Flat or tree-structured objects with independent atomic properties connected to a central room authority | Single-owner document server sequencing updates in arrival order with per-property Last-Writer-Wins (Server-Authoritative Per-Property LWW) | `Liveblocks` (`LiveObject`, `LiveMap`, `LiveList`) or a single-threaded per-document room actor (`Cloudflare Durable Objects`, `PartyKit`, or isolated room process) paired with `fractional-indexing` / `jittered-fractional-indexing` |
| Collaborative plain/rich text, ordered lists with concurrent splices or moves, offline peer merges, or E2EE documents | Maximal non-interleaving sequence/list CRDTs, logical-time style anchors, and event-graph walkers | `Loro 1.0` (`LoroText`, `LoroMovableList`), `Yjs` (`Y.Text`, `Y.XmlFragment`, `Y.Array` with `y-protocols`), or `Automerge 3` |
| Hierarchical trees allowing concurrent reparenting and subtree deletion without a central lock | Movable-tree CRDT unifying creation, movement, and trash-root deletion under total logical order with `Undo-Do-Redo` cycle resolution | `Loro 1.0` (`LoroTree` with Kleppmann's movable-tree algorithm and jittered Fractional Index) |
| Ephemeral session presence, live pointer coordinates, and viewport selections | Unjournaled broadcast channel paired with receiver-side curve interpolation | `y-protocols/awareness`, `Loro EphemeralStore`, or ephemeral room broadcast paired with `perfect-cursors` |
| Client-side persistent replica storage | Embedded local transactional store supporting atomic batch writes and reactive queries | `SQLite` (WASM on web or native on mobile/desktop), `PGlite`, or engine-managed `IndexedDB` (`y-indexeddb` / Replicache / Zero store) |

## 2. Architecture Branching & Multi-Plane Segregation

- **When** a system component requires concurrent conflict resolution, local replica persistence, relative sequence ordering, or realtime cursor smoothing, integrate the existing project primitive or the corresponding off-the-shelf primitive from the Closed Contract table and confine application code to domain schema mapping, permission gates, and storage adapters. Implementing custom Operational Transformation (`OT`) matrices, custom CRDT merge reducers, custom fractional-index math, or manual linear cursor timers in application code introduces protocol-edge divergence under concurrent load.
- **When** the validity of a mutation depends on a cross-record invariant, a sequential human-readable identifier, a global quota, or an authorization rule that only the server can verify, route the mutation through a **Transactional Rebase** pipeline: generate any new entity primary key (UUID/nanoid) at the call site *before* invoking the mutator and pass it in as an explicit argument, execute the deterministic speculative mutator against the local store with a monotonically increasing client-scoped `mutationID`, and re-execute that exact mutator inside a serialized transaction on the server while ignoring any push request with `mutationID <= client.lastMutationID`. Merging cross-entity business state through commutative CRDTs guarantees only that replicas converge to the same value—never that the converged value satisfies the business invariant—and generating random IDs or wall-clock timestamps inside a replayed mutator body mints duplicate records on every local rebase or network retry.
- **When** shared state consists of structured objects whose individual user interactions mutate discrete atomic properties through a central room server, represent the document as a flat property map (`Map<ObjectID, Map<Property, Value>>`) and resolve conflicts by arrival order at the single server instance owning that room (Server-Authoritative Per-Property LWW). Resolving conflicts at the whole-object level overwrites concurrent edits to sibling properties on the same entity, while attaching peer-to-peer vector clocks to discrete properties that always transit a central server adds metadata and garbage-collection overhead without improving convergence.
- **When** multiple users concurrently insert, delete, splice, or move elements within the same text span, ordered list, or uncoordinated tree—or when the application must merge offline edits peer-to-peer or under end-to-end encryption (E2EE) where the server cannot inspect plaintext—embed a specialized CRDT container (`Yjs`, `Loro`, or `Automerge`) on that specific field or subdocument and gate local writes into the CRDT using $O(1)$ monotonic revision or nonce comparisons (`version` / `versionNonce`) rather than $O(N)$ full-object serialization (`JSON.stringify`) on the UI thread. Storing collaborative text or concurrent lists inside a single LWW property drops concurrent edits from earlier peers, and serializing full element structures on the UI thread to detect dirty entries turns single-item updates into $O(N)$ frame stalls.
- **When** state reflects transient session activity (pointer coordinates, viewport bounds, playhead scrubbing, or active presenter/lock roles) whose cancellation on disconnect does not alter the saved document after the session ends, route it exclusively through an unjournaled ephemeral channel governed by a server-side heartbeat TTL, a grace-period `suspended` lease state keyed by `userId` for exclusive role/lock holders (restoring ownership immediately if the same `userId` reconnects before the grace timer expires, and releasing the lease only on timeout or explicit yield), and receiver-side viewport clamping that bounds rendered peer indicators by coordination role and activity recency while exempting the active role/lock holder from eviction. Writing transient session frames into the durable CRDT history or database bloats storage with permanent tombstones, and revoking an active presenter or lock holder's lease on the exact millisecond of a socket drop disrupts the room on a brief reconnect or page reload.
- **When** a collaborative system combines high-frequency in-document editing with immutable binary assets or cross-document organizational and authorization metadata (access control lists, folders, comments, tenant quotas), store binary payloads in content-addressable storage (CAS) referenced inside document state solely by immutable content ID, and synchronize cross-document relational metadata through a dedicated database change-stream subscription (PostgreSQL WAL / query-driven sync) separate from the document CRDT. Embedding raw binary or Base64 payloads inside document state JSON or initial sync frames stalls room hydration and socket throughput, and embedding access-control tables inside a client-mergeable document tree breaks relational integrity and allows stale replicas to bypass permission revocation.

## 3. Optimistic Reconciliation, Flicker Suppression & High-Frequency Coalescing

- **When** a client receives a server broadcast for an object property while holding one or more unacknowledged local writes in flight on that exact `(ObjectID, Property)` pair, keep the local optimistic value displayed and ignore incoming server updates for that pair until the server's acknowledged sequence watermark passes all pending local writes for that property; whenever the server rejects an optimistic mutation (`PERMISSION_DENIED` or validation failure), include the authoritative state of the rejected entity in the rejection payload so the client rolls back that entity deterministically. Applying older in-flight server echoes over unacknowledged local property writes snaps the active user's UI backward mid-interaction, and rejecting an optimistic write without returning the canonical entity value leaves the rejected client permanently desynchronized from the room.
- **When** the server commits canonical state changes in a Transactional Rebase architecture, deliver the authorized state delta $\Delta S$ and the client's acknowledged `lastMutationID` as a single atomic unit—either by sending a contentless **poke** over WebSocket/SSE that triggers the client to pull $(\Delta S, \text{lastMutationID})$ from an authorization-filtered Pull endpoint when push and pull channels are decoupled, or by transmitting $(\Delta S, \text{lastMutationID})$ in one atomic frame over an ordered per-client stream—and on the client rewind the local store to the prior base state, apply $\Delta S$, evict queued local mutations with `id <= lastMutationID`, and replay remaining mutations with `id > lastMutationID` inside one atomic transaction before repainting. Pushing raw mutation payloads over WebSockets without atomic pairing to each client's `lastMutationID` races with in-flight pushes, bypasses read-path row-level security, and corrupts derived state by merging server patches on top of dirty optimistic mutations.
- **When** continuous hardware input (pointer drag, freehand drawing, color-wheel scrubbing, or live text drafting) mutates state at display-frame intervals (60–120Hz), apply every frame immediately to local presentation state while coalescing outbound network updates at a fixed tick interval (20–40ms / 25–50Hz) into compact binary deltas containing only the final changed values of that tick:
  - For ephemeral pointer/viewport streams, interpolate received ticks along a smooth curve (`perfect-cursors` / spline interpolation) on remote clients.
  - For continuous gestures mutating a durable CRDT entity, stream intermediate ticks over the transient binary preview channel into an isolated remote preview cache, suppress incoming remote previews for any entity ID the local user is actively editing, filter all remote preview entities out of the local UI component's `onChange`/writeback pipeline before computing local CRDT mutations, and commit the final entity state into the durable CRDT store only once when the gesture settles while immediately evicting its preview entry upon CRDT commit. Broadcasting raw pointer events or committing every 60Hz intermediate frame into a CRDT document saturates socket queues and generates thousands of historical structs per gesture, while allowing the local UI render loop to write remote preview ghosts back into local state commits uncommitted remote previews into the local CRDT log.

## 4. Tree Cycle Safety, Ordered Sequences, Rich Text & Collaborative Undo

- **When** a user mutates the `parent` reference of a node in a server-authoritative hierarchy, traverse the target parent's ancestor chain to the document root on the server before accepting the mutation to reject any assignment that would make a node a descendant of itself, and on the client temporarily hide from rendering any nodes caught in an unconfirmed local optimistic cycle until the server's resolution arrives. Accepting `parent` pointer updates via independent per-property LWW without whole-path ancestor validation allows concurrent moves ($A \rightarrow B$ and $B \rightarrow A$) to form a detached cycle that hangs recursive tree traversals.
- **When** a hierarchical tree allows concurrent reparenting or subtree deletion offline or without a central server lock, use a Movable Tree CRDT container (`LoroTree`) that represents creation, movement, and deletion (moving the target node under a designated `TRASH` root) as a unified 4-tuple move operation `Move(t, p, m, c)` ordered by global logical time `(Lamport, PeerID)` and resolves out-of-order arrivals by undoing later operations, checking cycle safety, applying the arrived move, and redoing the undone operations (`Undo-Do-Redo`). Simulating tree or list moves via separate `Delete` and `Insert` operations duplicates subtrees when two users move the same branch concurrently or drops concurrent edits made inside a moved subtree.
- **When** sibling elements in a shared collection maintain relative order through a sort-key property, generate each position key as an arbitrary-precision lexicographical fractional index (`fractional-indexing` / `jittered-fractional-indexing`) with random jitter enabled and break ties deterministically using the unique peer or item ID—or anchor structural moves relative to a target item ID with deterministic boundary fallback if the target was concurrently deleted. Re-numbering integer array indices rewrites $O(N)$ sibling records per move, IEEE-754 `float64` midpoints exhaust 53 bits of mantissa precision after ~50 repeated insertions into the same gap, and unjittered fractional midpoints collide on identical keys under concurrent insertion, leaving zero numerical space to insert a third element between the colliding items.
- **When** multiple users concurrently edit text and rich-text formatting, bind the text field to a sequence CRDT featuring causal left/right origin tracking and logical-time formatting anchors (`LoroText` with Fugue/Peritext, `Y.Text`/`Y.XmlFragment` with YATA formatting attributes, or `Automerge 3` marks), configure explicit boundary-expansion behavior (`before` / `after` / `both` / `none`) for each mark type, and normalize all string offsets to a single character-encoding coordinate system (converting between JavaScript UTF-16 code units and UTF-8 byte or Unicode scalar offsets) at every boundary between the UI runtime and the sync engine. Wrapping rich text in nested DOM-style element tags breaks under overlapping concurrent formatting spans, and passing raw JavaScript UTF-16 string indices into a UTF-8 CRDT kernel splits multi-byte surrogate pairs (emoji or CJK characters) in half.
- **When** a user performs undo or redo in a collaborative session, invert only mutations authored by that local user and transform the opposing history stack against current document state at the moment of undo and redo so that undoing $N$ steps and immediately redoing $N$ steps leaves the document state completely unchanged:
  - On a CRDT container, disable the host UI editor's built-in undo stack, attach the CRDT's native `UndoManager` scoped strictly to the local origin (`trackedOrigins: new Set([localOrigin])`), and bound or clear the undo stack on session lifecycle boundaries so deleted items pinned by the undo manager (`keepItem`) do not permanently block garbage collection.
  - On a server-authoritative property store without a CRDT `UndoManager`, rewrite the redo entry with the property's current pre-undo value at undo time and rewrite the undo entry at redo time. Restoring global document snapshots on undo or replaying untransformed prior values on redo overwrites valid concurrent edits committed by collaborators while the user was stepping through history.

## 5. Replica Identity, Hydration Lifecycle, Offline Cutoffs, Partial Sync & Schema Evolution

- **When** instantiating a CRDT document replica in memory—on initial mount, local storage load, worker thread spawn, or browser tab duplication—allocate a fresh unique replica identifier (`PeerID` / `clientID` / `ActorId`) for that running instance before permitting any write; seed initial placeholder UI exclusively into the transient presentation layer at Frame-0 without writing default entities into the CRDT document or overwriting non-empty local persistence before network hydration completes; and during initial 1-RTT join (cached snapshot + state-vector diff), buffer incoming live stream frames—discarding buffered frames whose causal watermark is already covered by the hydrated snapshot and coalescing the remainder before draining. Allowing two parallel tabs, workers, or devices to share a persisted or cloned `PeerID` produces distinct operations with identical `(counter, PeerID)` keys that silently drop each other and cause permanent, unrecoverable document divergence; writing default entities into the CRDT at Frame-0 pollutes the room with rogue clocks or erases persisted state before the server snapshot arrives.
- **When** tracking synchronization progress across reconnects, advance the client's causal watermark exclusively from version numbers or state vectors stamped on server-acknowledged commits; whenever a reconnecting replica's last synced watermark predates the server's history-compaction cutoff (`shallow snapshot`) or exceeds the application's offline permission/time budget, force the client to load a fresh authoritative baseline snapshot and route its pending offline mutations into an explicit application-level validation and re-application workflow. Speculatively incrementing the server version watermark on the client for unacknowledged or non-mutating outbound frames drifts the client ahead of the server and triggers false full-state recovery overwrites, while directly merging pre-cutoff CRDT updates or blindly re-pushing expired offline transactions corrupts compacted state or overwrites revoked resources.
- **When** synchronizing subsets of a multi-tenant database down to client devices, partition the data stream into declarative query subsets with explicit authorization routing keys (`Shapes` in ElectricSQL, `Sync Rules` in PowerSync, or `ZQL` queries in Zero) without distorting business primary keys, and maintain an explicit per-partition sync-completion flag in the local database that local queries inspect before returning results. Executing local queries against a newly subscribed partition before its initial sync-completion flag is set returns false-empty result sets to the UI and business logic, and coupling partition routing to ad-hoc primary-key mutations leaks data across tenant boundaries.
- **When** evolving the schema of records synchronized across devices that may run different application versions concurrently, define the schema in application code with an explicit version tag on each record, apply changes exclusively via additive optional fields with defaults or bidirectional lenses / server-side in-flight translation, and preserve all unrecognized fields untouched when an older replica reads, modifies, and writes back a record. Storing schema definitions inside the concurrently mergeable CRDT document itself creates bootstrap cycles and non-deterministic migrations, and running destructive one-way field renames or stripping unknown fields on write causes older active devices to silently erase data written by newer devices.

## 6. Room Coordinator Durability, Compaction, Hibernation, Fencing & Backpressure

- **When** persisting a CRDT document to storage or partitioning a multi-page workspace, stream incremental binary update deltas emitted by `doc.on('update')` into an append-only log and periodically compact accumulated rows into a merged snapshot via `mergeUpdates` once the update count or byte size crosses a fixed threshold, and partition independent pages into lazy-loaded subdocuments or scoped snapshots that explicitly call `.load()` on activation and `.destroy()` on unload. Serializing and overwriting the full CRDT document on every edit turns $O(1)$ mutations into $O(N)$ I/O bottlenecks, and removing a subdocument without calling `.destroy()` leaks its event listeners and in-memory CRDT structs for the lifetime of the process.
- **When** implementing a stateful room coordinator backed by durable storage (including hibernatable edge actors such as Cloudflare Durable Objects or PartyKit), serialize per-connection metadata onto each socket (`serializeAttachment`) and rehydrate all session maps and persisted room state inside a concurrency-blocking initialization gate (`blockConcurrencyWhile`) upon wake; apply incoming mutations to memory and broadcast immediately while scheduling durable storage writes onto a debounced timer or actor alarm (`setAlarm`); and guard every storage flush with an atomic compare-and-swap version precondition (`If-Match: ETag` or fencing token) that immediately closes room sockets (`4001`) and relinquishes ownership on precondition failure (`412`). Assuming in-memory fields survive actor hibernation drops active sessions on wake, awaiting storage I/O inside the message handler causes head-of-line blocking for the entire room, and flushing to storage without conditional version fencing allows a zombie room instance to overwrite newer state committed by its successor.
- **When** multiplexing ephemeral presence frames and authoritative state frames over the same client transport connection, monitor each connection's pending outbound queue and drop outbound ephemeral frames first when pending messages exceed a soft congestion threshold, terminating the connection to force a watermark-based delta resync only when buffered authoritative bytes breach a hard memory cap or stall timeout. Treating cursor broadcasts and authoritative document updates with equal queue priority under network congestion starves document delivery behind stale pointer frames or prematurely disconnects slow clients whose bandwidth could still carry authoritative state deltas.

## 7. Completion Criterion

A realtime multi-user synchronization design, plan, or implementation is complete only when verified against an explicit evidence table demonstrating that:
1. **Closed-Contract Delegation**: Every conflict-resolution, sequence-ordering, cursor-interpolation, and local-storage path is bound to the repository's existing primitive or an off-the-shelf primitive from Section 1, with zero custom OT/CRDT merge algorithms or custom sequence-indexing math in application code.
2. **Three-Plane & CAS Segregation**: Ephemeral presence (with heartbeat TTL, grace-period lease suspension, and viewport clamping), collaborative document state ($O(1)$ revision-gated CRDT or per-property LWW), cross-document relational/authorization control planes, and content-addressable binary assets are decoupled across storage and transport pipelines.
3. **Boundary Invariant Verification**: All boundary conditions applicable to the system's topology—in-flight per-property flicker suppression, deterministic rejection rollback, atomic `(ΔS, lastMutationID)` rebase with caller-generated IDs, 30–60Hz binary coalescing with remote preview writeback isolation, ancestor cycle prevention / `MovableTree` `Undo-Do-Redo`, jittered fractional indexing with `PeerID` tie-breaking, UTF-16/UTF-8 index normalization, local-origin undo/redo invariance with editor-history deactivation, fresh per-instance `PeerID` allocation, Frame-0 anti-pollution, shallow-snapshot/offline-budget reload reconciliation, per-partition sync-completion readiness flags, unknown-field-preserving schema evolution, CAS split-brain storage fencing, and two-tier socket backpressure—have explicit enforcement mechanisms verified against code or plan contracts.
